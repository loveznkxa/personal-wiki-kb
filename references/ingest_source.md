# ingest_source 模块详细规则

## 源文件类型处理

摄入模块接受用户放入 `raw/` 目录的源文件。按以下规则分类处理：

| 文件类型 | 处理方式 |
|---------|----------|
| `.md` | 直接读取并执行预分析逻辑 |
| `.json` | 解析后提取文本字段，再执行预分析逻辑 |
| `.txt` 等可提取纯文本的文件 | 尝试按纯文本读取并处理；若成功提取文本，照常分析 |
| 无法提取文本的文件（如 `.pdf` 扫描件、图片、二进制文件） | 跳过，并向用户报告：“无法处理文件 `raw/xxx`：格式不支持，请转换为 Markdown 或 JSON 后重试” |

> 注意：无论何种类型，处理后均不修改 `raw/` 中的原始文件。

---

## 预分析逻辑

读取源文件后，执行以下判定：

1. **知识点提取**: 从源文件中提取主题词、实体名、关键概念及其关系
2. **置信度评估**: 基于来源质量（权威性、详尽度、结构清晰度）赋置信度（高/中/低）
   - 高：来自权威论文、官方文档、经过验证的事实
   - 中：来自高质量博客、技术文章、合理推断
   - 低：尚未验证的观点、推测性内容、来源不明
3. **Wiki 匹配**: 与 `wiki/index.md` 中已有条目比对
4. **状态判定**:
   - 新知识: 该主题在 `wiki/` 下无对应页面 → 创建
   - 更新知识: 已有页面但源文件提供新信息 → 按五级策略合并更新
   - 重复知识: 信息完全冗余 → 跳过并报告
5. **跨文件关联检测**: 若批量摄入，识别不同源文件间的主题重叠，避免重复创建

## 页面创建/更新规则

### 命名规范
- 使用小写字母，空格用连字符 `-` 替代
- 文件名保持简短但可辨识
- 示例: `wiki/entities/llm-rag.md`, `wiki/topics/knowledge-management.md`

### 更新合并五级精确协议

| 场景 | 操作 | 示例 |
|------|------|------|
| 1. 新信息补充 | 追加到对应章节末尾，标记 `[补充于 YYYY-MM-DD]` | 原"核心内容"章节追加新要点 |
| 2. 信息修正 | 保留原文 + 修正注释 `[修正于 YYYY-MM-DD: X→Y]` | 旧数据和修正数据并存 |
| 3. 观点冲突 | 创建 `## 不同观点` 区块，分别标注来源 | 不抹杀任何来源的立场 |
| 4. 信息冗余 | 合并去重，保留最早来源时间戳 | 相同事实保留最早引用 |
| 5. 置信度升级 | 元数据 `confidence` 字段升级，保留记录 | 低→中→高 |

### 版本元数据格式
```yaml
---
created: YYYY-MM-DD
updated: YYYY-MM-DD
version: 2
confidence: high | medium | low
sources:
  - raw/source1.md
  - raw/source2.md
---
```

### 人工复核标记（必须遵守）
- 置信度为 **低** 的页面，在正文标题下方第一行插入醒目标记：
  `> [⚠️ 待复核 - 置信度:低]`
- 页面中涉及具体数据、统计结论、单来源推断的段落，在该段落前标注 `[需人工验证]`

## 反向链接自动构建

- 创建/更新页面时，自动扫描 `[[wiki/xxx]]` 引用
- 为每个被引用的页面添加或更新反向链接区块
- 格式：
  
  ## 反向链接
  - [[wiki/entities/xxx]] — 引用于 YYYY-MM-DD
 
- 被引用页面不存在的，在 `index.md` 中相应类别下追加 `[待创建]` 条目

---

## 索引更新规则

`wiki/index.md` 必须按实体、主题、对比分析、待创建四类维护。格式示例：

# 知识库索引
最后更新: YYYY-MM-DD

## 实体 (Entities)
- [概念名称](entities/xxx.md) — 简短描述 `[置信度:高]`

## 主题 (Topics)
- [主题名称](topics/xxx.md) — 简短描述 `[置信度:中]`

## 对比分析 (Comparisons)
- [比较主题](comparisons/xxx.md) — 简短描述 `[置信度:高]`

## ⏳ 待创建页面
- [待创建概念] — 期望来源或说明

**增量更新策略**: 仅在变更页面范围内更新对应索引条目，不重写全量。

---

## 操作日志追加

每次成功创建或更新 Wiki 页面后，**必须** 在 `wiki/log.md` 末尾追加一条记录，格式：

```
YYYY-MM-DD HH:MM [ingest_source] 操作描述
```

示例：
```
2026-04-29 14:30 [ingest_source] 从 raw/llm-basics.md 创建 entities/large-language-model.md，置信度:高
2026-04-29 15:00 [ingest_source] 更新 entities/llm-rag.md，补充来源 raw/rag-survey.md
```

> 日志追加无需用户确认，由 Agent 自动执行。
