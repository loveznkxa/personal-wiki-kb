# 故障排除指南

| 问题 | 排查步骤 |
|------|----------|
| 摄入后页面未在索引中出现 | 检查 `wiki/index.md` 是否新增对应条目；检查 `raw/` 源文件是否完整且路径正确；查看 `wiki/log.md` 中是否有摄入记录 |
| 无法处理某些文件（如 .pdf、图片） | 确认文件是否为 `.md`、`.json` 或可提取文本的 `.txt`。不支持的格式需手动转换为 Markdown 后重新放入 `raw/` |
| 查询返回空结果或无关结果 | 确认 `wiki/` 目录非空；确认问题关键词与 `wiki/index.md` 中条目描述一致；必要时运行 `audit_wiki` 检查索引是否损坏 |
| 冲突信息未被标记 | 检查相关页面元数据中是否有冲突标记；若未发现，手动运行 `audit_wiki` 进行矛盾扫描 |
| 页面之间缺少反向链接 | 检查被引用页面是否存在；若存在但链接缺失，可手动在源页面中添加 `[[wiki/xxx]]` 并重新运行摄入或回写流程 |
| 索引文件损坏或不同步 | 运行 `audit_wiki`，该模块会扫描 `wiki/` 目录并全量重建索引 |
| 低置信度页面没有 `[⚠️ 待复核]` 标记 | 检查该页面元数据 `confidence` 是否为 `low`；若是，运行 `audit_wiki` 可检测并建议补充标记 |
| 操作日志（`wiki/log.md`）未更新 | 检查日志文件是否存在于 `wiki/` 目录；确保最近的操作确已完成（摄入、回写或审计），只有成功写入后才会追加日志 |
| 回写草案未自动触发 | 确认查询或审计过程是否真正产生了跨文档新结论、矛盾解决或深度阐释；若符合条件但未触发，可手动要求 AI：“将刚才的结论写入 Wiki” |
| 审计发现的问题没有自动修复 | 审计模块仅提供报告和建议，修复需人工执行或通过 `persist_knowledge` 生成修复草案。部分操作（如归档）审计模块会直接询问是否执行 |
| 归档后仍有页面引用了已归档文件 | 运行 `audit_wiki` 检查反向链接完整性；手动删除残留链接或要求 AI：“清理所有指向 `wiki/archive/xxx.md` 的链接” |
| 回写完成后系统似乎继续自动查询/审计 | 检查是否意外触发了第二次请求。系统已内置防循环规则，若持续发生，尝试开启新对话并明确单次指令边界 |
